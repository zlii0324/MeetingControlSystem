# Jitsi 会议预约与 Reservation 集成系统设计方案（V1）

## 1. 项目背景

公司已完成 Jitsi Server
的部署，希望在现有基础上开发一套企业级会议管理系统，实现：

-   创建会议
-   预约会议
-   会议管理
-   一次性会议密码
-   生成会议链接
-   与 Jitsi Reservation 模块集成
-   不使用 JWT 身份认证


Jitsi 负责音视频能力，业务系统负责会议生命周期管理。

# 3. 第一阶段目标（MVP）

实现以下功能：

-   创建会议
-   自动生成随机 Room ID
-   自动生成一次性会议密码
-   返回会议链接
-   保存会议信息到 SQLite
-   Reservation API 与 Jitsi 集成
-   查看会议列表
-   查看会议详情
-   取消会议

**暂不实现：**

-   邮件通知
-   ICS 日历邀请
-   用户登录
-   JWT
-   权限系统

------------------------------------------------------------------------

# 4. 前端设计

## 创建会议

输入：

-   会议标题
-   主持人
-   开始时间 (可选，默认当下时间)
-   结束时间 (可选，默认开始之后24hrs)

点击创建后：

系统生成：

-   Meeting URL
-   Meeting Password（仅显示一次）

支持复制链接和密码。

------------------------------------------------------------------------

## 我的会议

显示：

-   标题
-   状态
-   开始时间
-   结束时间
-   Room ID

操作：

-   查看详情
-   取消会议

------------------------------------------------------------------------

## 会议详情

展示：

-   标题
-   主持人
-   时间
-   Room ID
-   Meeting URL
-   当前状态

密码不再显示。

------------------------------------------------------------------------

# 5. 后端模块

## Meeting Service

负责：

-   创建会议
-   查询会议（查看状态）
-   更新会议
-   删除会议

创建会议时：

1.  生成 UUID Room ID
2.  生成随机密码
3.  Hash 密码
4.  保存 SQLite
5.  返回：

-   Meeting URL
-   Password

------------------------------------------------------------------------

## Reservation Service

提供：

### POST /conference

Prosody 创建会议时调用。

Reservation：

-   查询 SQLite
-   判断会议是否存在
-   判断状态
-   判断时间

返回：

-   meeting id
-   password
-   duration
-   lobby
-   max occupants

------------------------------------------------------------------------

### DELETE /conference/{id}

会议结束后：

更新数据库：

Finished

------------------------------------------------------------------------

# 6. 数据库

SQLite

## meetings

  字段            说明
  --------------- --------------------------------------
  id              PK
  room_id         UUID
  title           标题
  host_name       主持人
  start_time      开始
  end_time        结束
  duration        时长
  status          Scheduled/Running/Finished/Cancelled
  password_hash   Hash
  max_occupants   人数
  created_at      创建时间
  updated_at      更新时间

------------------------------------------------------------------------

## access_logs

记录：

-   IP
-   UserAgent
-   Join Time
-   Success
-   Fail Reason

# 11. 最终效果（第一阶段）

管理员创建会议后，系统生成：

-   Meeting URL
-   一次性会议密码

系统保存会议信息到 SQLite。

Jitsi 首次创建房间时，通过 Reservation API
查询会议配置，并自动应用密码、人数限制等设置，实现轻量级企业会议管理。
