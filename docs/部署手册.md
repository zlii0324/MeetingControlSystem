# 会议管理系统 (Meeting Control System) 部署手册

本手册基于在目标服务器 (`172.16.100.224`) 上的实际部署过程编写，旨在为您提供一套标准化的前后端部署与更新流程。

## 1. 基础环境准备

在开始部署之前，请确保目标服务器已安装以下依赖：

- **Git**: 用于拉取和更新最新代码。
- **Python 3 & pip**: 用于运行 Flask 后端，推荐安装并使用 `venv` 虚拟环境。
- **Node.js & npm**: 用于运行前端项目。建议使用 Node.js 版本 `v20+`（当前服务器已部署版本为 `v22.22.1`）。

---

## 2. 代码获取与更新

将代码克隆到服务器上（建议选择如 `/var/www/` 或用户主目录等合适位置）：

```bash
# 首次拉取代码
git clone https://github.com/zlii0324/MeetingControlSystem.git
cd MeetingControlSystem

# 若后续需要更新代码，只需拉取最新分支即可
git pull origin main
```

*(注：当前服务器部署位于 `/home/user01/.ssh/MeetingControlSystem`)*

---

## 3. 后端服务部署 (Flask API)

后端服务基于 Python 编写，使用 SQLite 作为数据库。

### 3.1 环境初始化

```bash
# 进入后端目录
cd backend

# 创建并激活 Python 虚拟环境
python3 -m venv venv
source venv/bin/activate

# 安装依赖
pip install -r requirements.txt

# 配置环境变量（根据实际情况修改 .env 中的配置）
cp .env.example .env
```

### 3.2 启动服务

您可以选择前台启动进行测试：
```bash
python app.py
```
*后端默认将运行在：`http://0.0.0.0:5001`*

**后台常驻运行推荐（nohup 方式）**：
```bash
nohup python app.py > backend.log 2>&1 &
```

*(如用于正式生产环境，建议配置 `systemd` 或使用 `gunicorn` 来托管运行)*

---

## 4. 前端服务部署 (React + Vite)

前端是一个基于 React + Ant Design 的单页日历 UI，使用 Vite 进行构建与托管。

### 4.1 安装依赖

```bash
# 进入前端目录
cd ../frontend

# 安装依赖模块
npm install

# 配置环境变量（可选，确认实际接口地址配置）
cp .env.example .env
```

### 4.2 启动服务

**后台常驻运行推荐**：
Vite 默认只绑定 `127.0.0.1`，我们需要绑定到 `0.0.0.0` 才能进行公网/局域网访问。项目中的 `package.json` 里的 `dev` 脚本已配置 `--host 0.0.0.0 --port 5173`。

使用 `nohup` 让其在后台持续运行：
```bash
nohup npm run dev > frontend.log 2>&1 &
```
启动成功后，即可通过浏览器访问：`http://<服务器IP>:5173/` (如: `http://172.16.100.224:5173/`)。

*(生产环境推荐构建静态文件：执行 `npm run build`，然后使用 Nginx 将流量代理到 `dist/` 文件夹。)*

## 5. 常见问题排查与维护

### 5.1 重新部署流程（代码更新后）
若通过 `git pull` 拉取了新代码，你需要重新启动服务：

**前端重启**：
```bash
# 1. 终止旧的 Vite 进程
pkill -f 'vite'
# 2. 重新安装可能的依赖变更并后台启动
cd frontend
npm install
nohup npm run dev > frontend.log 2>&1 &
```

**后端重启**：
```bash
# 1. 查找并终止 Python 进程 (端口 5001)
fuser -k 5001/tcp
# 2. 重新启动
cd backend
source venv/bin/activate
nohup python app.py > backend.log 2>&1 &
```

### 5.2 前端启动奔溃 (Bus error / core dumped)
在开发服务器 (`vite dev`) 启动期间，有时会出现 `Bus error (core dumped)` 错误导致进程异常终止，这种情况通常与缓存损坏或底层编译包在部分架构下的兼容性有关。

**解决办法**：
清除原有的 `node_modules` 目录以及 `package-lock.json`，然后重新安装依赖即可。
```bash
cd frontend
rm -rf node_modules package-lock.json
npm install
nohup npm run dev > frontend.log 2>&1 &
```
