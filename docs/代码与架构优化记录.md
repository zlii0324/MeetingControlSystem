# 会议管理系统 (Meeting Control System) 架构与代码优化记录

本文档记录了在此次部署和调优过程中，对系统底层环境、前后端代码及架构所做的所有核心修改和优化。

## 1. 操作系统与终端环境优化
**问题表现**：通过 SSH 访问服务器并在终端执行命令（如 `ls`）时，中文文件名显示为乱码。
**解决措施**：
- 在服务器的 `/home/user01/.bashrc` 文件末尾强制追加了中文 UTF-8 环境变量配置。
- 确保服务端向客户端输出文本时采用统一的 UTF-8 编码，彻底解决了乱码问题。
```bash
# ~/.bashrc 追加内容
export LANG=zh_CN.UTF-8
export LC_ALL=zh_CN.UTF-8
```

## 2. 后端架构与代码级性能优化 (Backend)
**问题表现**：原先使用 `nohup python app.py` 启动 Flask 自带开发服务器，并发承载力弱且容易崩溃；SQLite 默认模式在并发读写时容易产生锁等待。
**解决措施**：
1. **替换为 Gunicorn 生产级网关**：抛弃了 Flask 自带的开发服务器，引入了 `gunicorn`，并配置了多进程+多线程模型 (`--workers 3 --threads 4 --worker-class gthread`)，理论并发承载能力直接提升数倍。
2. **引入 Systemd 进程守护**：编写了 `/etc/systemd/system/meeting-backend.service`，接管了后端的生命周期，实现了开机自启和崩溃自动重启，并规范了日志输出。
3. **SQLite 性能调优**：修改了 `backend/database.py` 中的数据库连接初始化代码，注入了高级 PRAGMA 指令：
   ```python
   # backend/database.py 修改点
   conn = sqlite3.connect(db_path, timeout=10.0)
   conn.row_factory = sqlite3.Row
   conn.execute("PRAGMA foreign_keys = ON")
   conn.execute("PRAGMA journal_mode = WAL")      # 开启写前日志，允许读写并发
   conn.execute("PRAGMA synchronous = NORMAL")    # 优化磁盘 I/O 等待
   conn.execute("PRAGMA cache_size = -64000")     # 提升缓存到约 64MB
   ```

## 3. 前端部署模式与 Bug 修复 (Frontend)
**问题表现**：原先使用 `npm run dev` 运行在开发模式下，页面体积大、加载慢。且在修复过程中，遇到 `.env.production` 环境变量配置错误导致严重的跨域 (CORS) Bug。
**解决措施**：
1. **修复 API 路由拼接 Bug**：
   - 之前 `.env.production` 中的 `VITE_API_BASE_URL=/` 会导致 `fetch` 拼接出 `//api/meetings` 这种“协议相对 URL”。浏览器将其误认为是一个名为 `api` 的跨站域名，从而发起 `OPTIONS` 预检请求导致 500 报错。
   - **修正**：将其改为了 `VITE_API_BASE_URL=`（空字符串），确保请求能够正确落在当前域名的 `/api/meetings` 下。
2. **生产环境编译 (Production Build)**：执行了 `npm run build`，利用 Vite 进行了 JS/CSS 代码的极致压缩 (Minification) 和 Tree-shaking，去除了开发模式冗余代码。
3. **安全目录转移**：将打包后的静态产物从带有严苛权限限制的 `~/.ssh/...` 目录迁移到了标准 Web 目录 `/var/www/meeting-frontend`，并将权限赋予 `www-data`。

## 4. Nginx 生产级网关搭建
**问题表现**：无统一网关，前后端端口暴露混乱，存在跨域风险和极大的性能浪费。
**解决措施**：
- 在服务器上安装并配置了 Nginx，监听 80 端口，统一处理所有外部请求。
- **静态资源直出与加速**：Nginx 直接读取 `/var/www/meeting-frontend` 下的前端构建产物。
- **Gzip 压缩传输**：开启 `gzip`，使 JS/CSS 的网络传输体积缩小了近 70%。
- **强缓存策略**：为 `/assets/` 目录设置了为期 1 年的强缓存 (`max-age=31536000, immutable`)。
- **统一 API 代理**：配置了 `location /api/`，在系统内部将 API 请求无缝转发到 Gunicorn 的 `127.0.0.1:5001`，彻底规避了浏览器的跨域拦截机制。
