# 会议管理系统操作文档

## 1. 系统说明

本系统用于管理 Jitsi 会议预约，业务系统负责会议生命周期，Jitsi 负责音视频会议。

第一阶段功能：

- 创建会议
- 编辑会议标题、创建者、参会者、会议时间、最大人数、等候室
- 日历查看所有会议
- 查看会议详情和 Jitsi 链接
- 删除会议，系统会从数据库中移除会议
- 生成一次性会议密码，密码只在创建成功后展示一次
- 管理端账号登录、用户注册申请与管理员审核
- 邮件一次性链接找回密码，以及管理员协助的临时密码重置
- 预留 Jitsi Reservation API：`POST /conference`、`GET /conference/{id}`、`DELETE /conference/{id}`

当前阶段先不用配置 Prosody。预约会议由“创建会议并保存到系统数据库”完成；数据库可使用 MySQL，未配置 MySQL 时使用 SQLite，生成的会议链接直接指向 Jitsi。

默认 Jitsi 地址：

```text
https://meet.wusupower.com/
```

## 3. 本地启动与裸机部署

下面的步骤适用于直接部署到 Ubuntu/CentOS 这类裸机服务器。

### 3.1 后端部署

```bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
touch .env
python manage.py create-admin
python app.py
```

默认监听地址：

```text
http://0.0.0.0:5001
```

健康检查：

```bash
curl http://127.0.0.1:5001/api/health
```

生产环境建议改为 Gunicorn 启动：

```bash
source venv/bin/activate
gunicorn --bind 0.0.0.0:5001 --workers 2 app:app
```

### 3.2 前端部署

```bash
cd frontend
npm install
touch .env
npm run build
```

构建产物会生成 `frontend/dist` 目录。可以直接用 Python 的静态文件服务启动：

```bash
cd frontend/dist
python3 -m http.server 3000
```

前端默认地址：

```text
http://你的服务器IP:3000
```

### 3.3 服务器外部访问说明

如果从外部访问，请把所有 `localhost` 替换为公网域名或服务器 IP，例如：

```text
FRONTEND_ORIGIN=https://meeting.example.com
VITE_API_BASE_URL=https://api.example.com
```

如果前端和后端部署在同一台机器上，且前端通过同域名访问后端，则可以把前端接口地址配置为 `/`，这样前端会走当前域名下的相对路径。

## 4. 环境变量

后端配置文件：`backend/.env`

```env
# MySQL 主配置全部留空时自动使用 SQLite
DATABASE_PATH=./instance/meetings.sqlite3
DATABASE_HOST=
DATABASE_PORT=3306
DATABASE_NAME=
DATABASE_USERNAME=
DATABASE_PASSWORD=
DATABASE_CHARSET=utf8mb4
DATABASE_POOL_SIZE=10
DATABASE_POOL_RECYCLE_SECONDS=1800
JITSI_BASE_URL=https://meet.wusupower.com/
JITSI_JWT_APP_ID=meeting-control-production
JITSI_JWT_APP_SECRET=请使用高强度随机密钥并通过密钥管理系统注入
JITSI_JWT_SUBJECT=meet.wusupower.com
JITSI_JWT_TTL_SECONDS=7200
ROOM_PREFIX=mcs
FRONTEND_ORIGIN=https://meeting.example.com
PASSWORD_SECRET=change-this-long-random-secret-before-production
DEFAULT_DURATION_HOURS=24
DEFAULT_MAX_OCCUPANTS=30
RESERVATION_EARLY_JOIN_MINUTES=15
ENABLE_CORS=true
SESSION_COOKIE_NAME=mcs_session
SESSION_TTL_DAYS=7
SESSION_COOKIE_SECURE=false
SESSION_COOKIE_SAMESITE=Lax
EMAIL_NOTIFICATIONS_ENABLED=false
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=meetings@example.com
SMTP_PASSWORD=replace-with-app-password
SMTP_USE_TLS=true
SMTP_USE_SSL=false
SMTP_VERIFY_CERTIFICATE=true
SMTP_TIMEOUT_SECONDS=10
EMAIL_FROM=meetings@example.com
EMAIL_FROM_NAME=会议管理系统
EMAIL_TIMEZONE=Asia/Shanghai
```

重要配置：

- `JITSI_BASE_URL`：生成会议链接时使用的 Jitsi 地址。
- `JITSI_JWT_APP_ID` / `JITSI_JWT_APP_SECRET`：启用 JWT 签发，必须与 Jitsi Prosody 的 `JWT_APP_ID` / `JWT_APP_SECRET` 相同。
- `JITSI_JWT_SUBJECT`：JWT 的 `sub`，必须对应 Jitsi 的 `XMPP_DOMAIN`。
- `JITSI_JWT_TTL_SECONDS`：入会 token 有效期，默认 7200 秒。
- `FRONTEND_ORIGIN`：生成的会议访问链接会指向这里，生产环境必须改成公网地址。
- `PASSWORD_SECRET`：用于加密保存会议密码，生产环境必须换成高强度随机字符串。
- `RESERVATION_EARLY_JOIN_MINUTES`：允许提前进入会议的分钟数。
- `DEFAULT_MAX_OCCUPANTS`：默认最大参会人数。
- `SESSION_TTL_DAYS`：管理端登录有效天数。
- `SESSION_COOKIE_SECURE`：生产环境使用 HTTPS 时建议设为 `true`。
- `EMAIL_NOTIFICATIONS_ENABLED`：设为 `true` 后启用参会者邮件通知。
- `SMTP_HOST`、`SMTP_PORT`：发件邮箱服务商提供的 SMTP 服务器和端口。
- `SMTP_USERNAME`、`SMTP_PASSWORD`：SMTP 登录账号和应用专用密码。不要提交真实密码到 Git。
- `SMTP_USE_TLS`：端口通常为 `587` 时使用 STARTTLS。
- `SMTP_USE_SSL`：端口通常为 `465` 时使用 SSL；启用时应将 `SMTP_USE_TLS` 设为 `false`。
- `SMTP_VERIFY_CERTIFICATE`：生产环境应保持 `true`；仅自签名邮件服务器测试时才设为 `false`。
- `EMAIL_FROM`、`EMAIL_FROM_NAME`：通知邮件显示的发件地址和名称。
- `EMAIL_TIMEZONE`：通知邮件显示会议时间所使用的时区。
- `PASSWORD_RESET_URL_ORIGIN`：密码重置邮件中的前端地址；不填时复用 `MEETING_LINK_ORIGIN`。
- `PASSWORD_RESET_TOKEN_TTL_MINUTES`：邮件重置链接有效期，默认 30 分钟。
- `PASSWORD_RESET_COOLDOWN_SECONDS`：同一账号重复发送邮件的最短间隔，默认 60 秒。

前端配置文件：`frontend/.env`

```env
VITE_API_BASE_URL=/
VITE_JOIN_LINK_ORIGIN=
```

如果前端和后端不在同一域名下，则改成：

```env
VITE_API_BASE_URL=https://api.example.com
```

## 5. 页面操作

### 5.0 登录与账号审核

首次部署后，先在后端目录创建管理员：

```bash
cd backend
python manage.py create-admin
```

普通用户可以使用用户名或邮箱登录。在登录页点击“申请账号”后，可填写用户名、用户昵称（真实姓名）、邮箱、密码和给管理员的留言。邮箱为必填，且不能与其他账号重复。申请提交后账号状态为待审核，不能直接登录。

管理员登录后，在左侧“账号审核”区域查看待审核用户，可以选择“通过”或“拒绝”。通过后用户获得会议管理权限，可以创建、编辑和删除会议。

管理员可以在“用户管理”里新建、编辑、删除用户，也可以重置用户密码。系统会保护最后一个可用管理员账号，不能删除、停用或降级最后一个 `active admin`。

用户密码不会以明文或可逆加密形式保存，数据库只保存加盐哈希。用户忘记密码时，在登录页点击“找回密码”，可以选择“邮件找回”或“管理员协助”。邮件找回会向账号绑定邮箱发送限时、一次性链接，用户打开链接后直接设置新密码；系统只保存链接令牌的哈希，链接使用后立即失效，并让旧会话失效。邮件接口不会透露邮箱是否已注册。无法接收邮件时，可填写用户名或邮箱及说明提交管理员申请；管理员确认后，系统生成临时密码并让旧会话失效，临时密码只在处理结果里展示一次。

创建或编辑会议时，在参会者输入框中输入姓名、用户名或邮箱，系统会像搜索框一样显示匹配的有效账号，并同时展示姓名、用户名和邮箱以便区分同名用户。新增的系统用户必须从补全列表中选择，选中后保存其唯一邮箱；外部参会者也可以直接输入完整邮箱并按回车添加。创建会议时通知全部可识别参会者，编辑会议时只通知新加入的参会者，重复保存不会重复发送。周期会议只发送一封汇总邀请，邮件包含会议时间、参与链接和会议密码。SMTP 未启用或发送失败不会撤销已经保存的会议，页面会显示相应警告。

建议至少创建两个不同管理员账号，由不同可信人员保管；不要复制同一个管理员密码。若所有管理员都忘记密码但仍能登录服务器，可以在后端目录运行：

```bash
python manage.py create-admin
```

创建新的管理员账号，或运行：

```bash
python manage.py reset-password 用户名
```

为指定账号生成临时密码。

### 5.1 创建会议

1. 打开前端页面并登录。
2. 点击左侧“创建会议”按钮。
3. 填写：
   - Title
   - 主持人，默认使用当前登录用户的用户昵称（真实姓名），也可以手动更改
   - 参会者名单
   - 开始时间 / 结束时间
   - 最大人数
   - 是否启用等候室
4. 点击“创建”。
5. 系统展示会议链接和一次性会议密码。

注意：会议密码只在创建成功后展示一次，详情页不会再次显示密码。

### 5.2 查看会议

右侧日历会展示所有会议实体。点击日历中的会议，可以查看：

- 会议标题
- Room ID
- Jitsi 会议链接
- 创建者
- 开始时间
- 结束时间
- 最大人数
- 等候室状态
- 参会者名单

### 5.3 编辑会议

1. 点击日历中的会议。
2. 在右侧详情抽屉点击“编辑”。
3. 修改会议信息。
4. 点击“保存”。

已结束或已取消的会议不能编辑。

### 5.4 删除会议

1. 点击日历中的会议。
2. 在详情抽屉点击“删除”。
3. 确认删除。

删除后系统会在当前数据库中取消该会议，日历中不再显示为可用会议。

## 6. API 说明

### 6.1 创建会议

```http
POST /api/meetings
Content-Type: application/json
```

示例：

```json
{
  "title": "项目例会",
  "hostName": "William Li",
  "attendees": ["Alice", "Bob", "cathy@example.com"],
  "startTime": "2026-07-07T09:00:00.000Z",
  "endTime": "2026-07-07T10:00:00.000Z",
  "maxOccupants": 30,
  "lobbyEnabled": false
}
```

返回中包含：

- `meetingUrl`
- `password`

`password` 只在创建接口返回。

### 6.2 获取会议列表

```http
GET /api/meetings
```

### 6.3 获取会议详情

```http
GET /api/meetings/{id}
```

### 6.4 编辑会议

```http
PUT /api/meetings/{id}
Content-Type: application/json
```

### 6.5 删除会议

```http
DELETE /api/meetings/{id}
```

## 7. 当前阶段的 Jitsi 使用方式

当前阶段不用 Prosody Reservation。

系统创建会议后会生成：

```text
https://meet.wusupower.com/{roomId}
```

用户拿到链接和创建时展示的一次性密码后，直接打开该 Jitsi 链接参会。会议信息、参会者、开始时间和结束时间都保存在本系统当前使用的 MySQL 或 SQLite 数据库中。

## 8. 后续预留：Jitsi Reservation 对接

Jitsi 官方 Reservation 模块会在会议房间首次创建前调用外部系统的 `/conference` 接口。官方文档说明，Prosody 会发送 `POST /conference`，请求体为 `application/x-www-form-urlencoded`，成功响应需要包含会议 `id` 和秒级 `duration`；启用密码支持后，响应中的 `password` 会被设置为房间密码。

官方参考：

- [Jitsi Reservation System setup](https://jitsi.github.io/handbook/docs/devops-guide/reservation/)
- [mod_reservations.lua](https://github.com/jitsi/jitsi-meet/blob/master/resources/prosody-plugins/mod_reservations.lua)

### 8.1 后端公网地址

Jitsi 服务器必须能访问后端 Reservation API。假设后端公网地址为：

```text
https://meeting-api.example.com
```

则 Prosody 要配置：

```lua
reservations_api_prefix = "https://meeting-api.example.com"
```

Prosody 实际会请求：

```text
https://meeting-api.example.com/conference
```

### 8.2 Prosody 配置模板

在 Jitsi 服务器上编辑 Prosody 虚拟主机配置，常见路径类似：

```text
/etc/prosody/conf.avail/meet.wusupower.com.cfg.lua
```

在主 `VirtualHost "meet.wusupower.com"` 中加入或确认：

```lua
VirtualHost "meet.wusupower.com"
    modules_enabled = {
        -- existing modules...
        "reservations";
    }

    reservations_api_prefix = "https://meeting-api.example.com"
    reservations_api_timeout = 10
    reservations_api_retry_count = 3
    reservations_api_retry_delay = 1

    reservations_enable_password_support = true
    reservations_enable_max_occupants = true
    reservations_enable_lobby_support = true
```

如需启用最大人数限制，Jitsi/Prosody 侧还需要启用对应的 `muc_max_occupants` 模块。

如需启用等候室，Jitsi/Prosody 侧还需要启用 `muc_lobby_rooms` 和 `persistent_lobby`。

### 8.3 重启 Jitsi 服务

配置完成后重启相关服务：

```bash
sudo systemctl restart prosody
sudo systemctl restart jicofo
sudo systemctl restart jitsi-videobridge2
```

如果你是裸机部署，直接在 Jitsi 服务器上把 `reservations_api_prefix` 指向后端公网地址即可即可。

## 9. Reservation 接口测试

本节为后续启用 Prosody 时使用。当前阶段可以跳过。

创建会议后拿到 `roomId`，例如：

```text
mcs-7a1d8c4f3b2e
```

模拟 Prosody 调用：

```bash
curl -X POST https://meeting-api.example.com/conference \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "name=mcs-7a1d8c4f3b2e&start_time=2026-07-07T09:00:00.000Z&mail_owner=admin@example.com"
```

成功返回示例：

```json
{
  "id": 1,
  "name": "mcs-7a1d8c4f3b2e",
  "mail_owner": "admin@example.com",
  "start_time": "2026-07-07T09:00:00.000Z",
  "duration": 3600,
  "password": "Ab12-Cd34-Ef56-Gh78",
  "max_occupants": 30
}
```

当会议被删除、结束、未到允许入会时间或 Room ID 不存在时，接口会返回 4xx。

## 10. 生产部署建议

- 后端使用 HTTPS 暴露给 Jitsi Prosody，建议使用云厂商负载均衡或反向代理，但本项目文档以裸机直接运行为主。
- `PASSWORD_SECRET` 必须使用生产随机密钥，并妥善备份。
- 使用 SQLite 时定期备份 `DATABASE_PATH` 指向的文件；使用 MySQL 时配置数据库服务端的定期备份和恢复演练。
- 直接在服务器上用 `systemd`、`supervisord` 或 `tmux` 持续运行后端和前端进程。
- 限制 `/api/*` 管理接口访问来源，第一阶段未实现登录鉴权。
- 当前阶段不用开放 `/conference` 给 Jitsi；后续启用 Prosody Reservation 时再允许 Jitsi 服务器访问。
- 如果前端和后端不是同域，配置 `FRONTEND_ORIGIN` 和 `VITE_API_BASE_URL`。

## 11. 常见问题

### 会议链接打开后没有触发 Reservation

当前阶段未启用 Prosody Reservation，所以不会触发 Reservation。后续启用时再检查 Jitsi Prosody 是否启用了 `reservations` 模块，以及 `reservations_api_prefix` 是否指向后端公网地址。

### 用户进会时没有要求输入密码

确认 Prosody 配置中启用了：

```lua
reservations_enable_password_support = true
```

同时确认会议是通过本系统创建，且 Room ID 与 Jitsi URL 最后一段一致。

### Jitsi 无法访问后端

在 Jitsi 服务器上执行：

```bash
curl https://meeting-api.example.com/api/health
```

如果无法访问，先检查防火墙、DNS、HTTPS 证书和反向代理。
