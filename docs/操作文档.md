# 会议管理系统操作文档

## 1. 系统说明

本系统用于管理 Jitsi 会议预约，业务系统负责会议生命周期，Jitsi 负责音视频会议。

第一阶段功能：

- 创建会议
- 编辑会议标题、创建者、参会者、会议时间、最大人数、等候室
- 日历查看所有会议
- 查看会议详情和 Jitsi 链接
- 删除会议，系统会从数据库中移除会议
- 生成一次性会议密码，密码只在创建成功后展示一次
- 预留 Jitsi Reservation API：`POST /conference`、`GET /conference/{id}`、`DELETE /conference/{id}`

当前阶段先不用配置 Prosody。预约会议由“创建会议并保存到 SQLite 数据库”完成，生成的会议链接直接指向 Jitsi。

默认 Jitsi 地址：

```text
https://meet.wusupower.com/
```

## 3. 本地启动

### 3.1 启动后端

```bash
cd backend
source ../venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python app.py
```

后端默认地址：

```text
http://localhost:5001
```

健康检查：

```bash
curl http://localhost:5001/api/health
```

### 3.2 启动前端

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

前端默认地址：

```text
http://localhost:5173
```

## 4. 环境变量

后端配置文件：`backend/.env`

```env
DATABASE_PATH=./instance/meetings.sqlite3
JITSI_BASE_URL=https://meet.wusupower.com/
ROOM_PREFIX=mcs
FRONTEND_ORIGIN=http://localhost:5173
PASSWORD_SECRET=change-this-long-random-secret-before-production
DEFAULT_DURATION_HOURS=24
DEFAULT_MAX_OCCUPANTS=30
RESERVATION_EARLY_JOIN_MINUTES=15
ENABLE_CORS=true
```

重要配置：

- `JITSI_BASE_URL`：生成会议链接时使用的 Jitsi 地址。
- `PASSWORD_SECRET`：用于加密保存会议密码，生产环境必须换成高强度随机字符串。
- `RESERVATION_EARLY_JOIN_MINUTES`：允许提前进入会议的分钟数。
- `DEFAULT_MAX_OCCUPANTS`：默认最大参会人数。

前端配置文件：`frontend/.env`

```env
VITE_API_BASE_URL=http://localhost:5001
```

生产环境要改为后端公网 HTTPS 地址。

## 5. 页面操作

### 5.1 创建会议

1. 打开前端页面。
2. 点击左侧“创建会议”按钮。
3. 填写：
   - Title
   - 创建者名字
   - 参会者名单
   - 开始时间 / 结束时间
   - 最大人数
   - 是否启用等候室
4. 点击“创建”。
5. 系统展示会议链接和一次性会议密码。

注意：会议密码只在创建成功后展示一次，详情页不会再次显示密码。

### 5.2 查看会议

右侧日历会展示所有会议实体。点击日历中的会议，可以查看：

- 会议标题
- Room ID
- Jitsi 会议链接
- 创建者
- 开始时间
- 结束时间
- 最大人数
- 等候室状态
- 参会者名单

### 5.3 编辑会议

1. 点击日历中的会议。
2. 在右侧详情抽屉点击“编辑”。
3. 修改会议信息。
4. 点击“保存”。

已结束或已取消的会议不能编辑。

### 5.4 删除会议

1. 点击日历中的会议。
2. 在详情抽屉点击“删除”。
3. 确认删除。

删除后系统会从 SQLite 数据库中移除该会议，日历中不再显示。

## 6. API 说明

### 6.1 创建会议

```http
POST /api/meetings
Content-Type: application/json
```

示例：

```json
{
  "title": "项目例会",
  "hostName": "William Li",
  "attendees": ["Alice", "Bob", "cathy@example.com"],
  "startTime": "2026-07-07T09:00:00.000Z",
  "endTime": "2026-07-07T10:00:00.000Z",
  "maxOccupants": 30,
  "lobbyEnabled": false
}
```

返回中包含：

- `meetingUrl`
- `password`

`password` 只在创建接口返回。

### 6.2 获取会议列表

```http
GET /api/meetings
```

### 6.3 获取会议详情

```http
GET /api/meetings/{id}
```

### 6.4 编辑会议

```http
PUT /api/meetings/{id}
Content-Type: application/json
```

### 6.5 删除会议

```http
DELETE /api/meetings/{id}
```

## 7. 当前阶段的 Jitsi 使用方式

当前阶段不用 Prosody Reservation。

系统创建会议后会生成：

```text
https://meet.wusupower.com/{roomId}
```

用户拿到链接和创建时展示的一次性密码后，直接打开该 Jitsi 链接参会。会议信息、参会者、开始时间和结束时间都保存在本系统 SQLite 数据库中。

## 8. 后续预留：Jitsi Reservation 对接

Jitsi 官方 Reservation 模块会在会议房间首次创建前调用外部系统的 `/conference` 接口。官方文档说明，Prosody 会发送 `POST /conference`，请求体为 `application/x-www-form-urlencoded`，成功响应需要包含会议 `id` 和秒级 `duration`；启用密码支持后，响应中的 `password` 会被设置为房间密码。

官方参考：

- [Jitsi Reservation System setup](https://jitsi.github.io/handbook/docs/devops-guide/reservation/)
- [mod_reservations.lua](https://github.com/jitsi/jitsi-meet/blob/master/resources/prosody-plugins/mod_reservations.lua)

### 8.1 后端公网地址

Jitsi 服务器必须能访问后端 Reservation API。假设后端公网地址为：

```text
https://meeting-api.example.com
```

则 Prosody 要配置：

```lua
reservations_api_prefix = "https://meeting-api.example.com"
```

Prosody 实际会请求：

```text
https://meeting-api.example.com/conference
```

### 8.2 Prosody 配置模板

在 Jitsi 服务器上编辑 Prosody 虚拟主机配置，常见路径类似：

```text
/etc/prosody/conf.avail/meet.wusupower.com.cfg.lua
```

在主 `VirtualHost "meet.wusupower.com"` 中加入或确认：

```lua
VirtualHost "meet.wusupower.com"
    modules_enabled = {
        -- existing modules...
        "reservations";
    }

    reservations_api_prefix = "https://meeting-api.example.com"
    reservations_api_timeout = 10
    reservations_api_retry_count = 3
    reservations_api_retry_delay = 1

    reservations_enable_password_support = true
    reservations_enable_max_occupants = true
    reservations_enable_lobby_support = true
```

如需启用最大人数限制，Jitsi/Prosody 侧还需要启用对应的 `muc_max_occupants` 模块。

如需启用等候室，Jitsi/Prosody 侧还需要启用 `muc_lobby_rooms` 和 `persistent_lobby`。

### 8.3 重启 Jitsi 服务

配置完成后重启相关服务：

```bash
sudo systemctl restart prosody
sudo systemctl restart jicofo
sudo systemctl restart jitsi-videobridge2
```

Docker 部署时，应在 Jitsi Docker `.env` 中启用：

```env
PROSODY_RESERVATION_ENABLED=true
PROSODY_RESERVATION_REST_BASE_URL=https://meeting-api.example.com
```

具体变量名以当前 Jitsi Docker 版本为准。

## 9. Reservation 接口测试

本节为后续启用 Prosody 时使用。当前阶段可以跳过。

创建会议后拿到 `roomId`，例如：

```text
mcs-7a1d8c4f3b2e
```

模拟 Prosody 调用：

```bash
curl -X POST http://localhost:5001/conference \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "name=mcs-7a1d8c4f3b2e&start_time=2026-07-07T09:00:00.000Z&mail_owner=admin@example.com"
```

成功返回示例：

```json
{
  "id": 1,
  "name": "mcs-7a1d8c4f3b2e",
  "mail_owner": "admin@example.com",
  "start_time": "2026-07-07T09:00:00.000Z",
  "duration": 3600,
  "password": "Ab12-Cd34-Ef56-Gh78",
  "max_occupants": 30
}
```

当会议被删除、结束、未到允许入会时间或 Room ID 不存在时，接口会返回 4xx。

## 10. 生产部署建议

- 后端使用 HTTPS 暴露给 Jitsi Prosody。
- `PASSWORD_SECRET` 必须使用生产随机密钥，并妥善备份。
- SQLite 文件定期备份，路径由 `DATABASE_PATH` 控制。
- 使用 Nginx 或 Caddy 反向代理后端。
- 限制 `/api/*` 管理接口访问来源，第一阶段未实现登录鉴权。
- 当前阶段不用开放 `/conference` 给 Jitsi；后续启用 Prosody Reservation 时再允许 Jitsi 服务器访问。
- 如果前端和后端不是同域，配置 `FRONTEND_ORIGIN` 和 `VITE_API_BASE_URL`。

## 11. 常见问题

### 会议链接打开后没有触发 Reservation

当前阶段未启用 Prosody Reservation，所以不会触发 Reservation。后续启用时再检查 Jitsi Prosody 是否启用了 `reservations` 模块，以及 `reservations_api_prefix` 是否指向后端公网地址。

### 用户进会时没有要求输入密码

确认 Prosody 配置中启用了：

```lua
reservations_enable_password_support = true
```

同时确认会议是通过本系统创建，且 Room ID 与 Jitsi URL 最后一段一致。

### Jitsi 无法访问后端

在 Jitsi 服务器上执行：

```bash
curl https://meeting-api.example.com/api/health
```

如果无法访问，先检查防火墙、DNS、HTTPS 证书和反向代理。
